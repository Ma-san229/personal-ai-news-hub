## 照合で見つけた問題（優先順）

1. **公開ページが自動更新されていない可能性が高い（⚠）**。deploy-pages.yml の実行履歴は全期間で8回だけで、すべてmainへのマージ時でした。6時間ごとの収集コミット（#286〜#304）の後に、公開の実行はありません。GITHUB_PAGES.mdの「コミットを契機に公開」という記述と食い違います。直し方は、収集の最後に公開を起動するか、収集ワークフロー内で公開まで行うことです。公開URLの現在の内容は、この環境から取得できず未確認です。
2. **AI要約が付いていない（⚠）**。最新の日次JSONに `summarizedBy` も示唆もありません。OPENROUTER_API_KEYの未設定、またはモデル名の無効が疑われますが、原因は未確認です。
3. **点数付けと採用履歴はまだ本線に入っていない（🟡）**。PR 4をマージするまで、選定は新しい順のままです。
4. **採用履歴の戻りが手作業**。PR 4の設計上の制約で、Discordの反応で自動化する計画の動機になります。
5. **同じリポジトリに別系統がある（❓）**。`client/` `server/` `drizzle/` の動的アプリと、`pages/` の静的ポータルが共存します。OPERATIONS.mdは「定期取得の実行場所は一方に統一」としています。PR 1（ドラフト）には、Gemini選定とDiscord通知を動的アプリ側に入れた別実装があり、今回の設計と重複します。どちらを本線にするか、決めが必要です。
6. **収集元の疎通が未確認**。feeds.json の各フィードのlastStatusは、今回は読んでいません（未確認）。
